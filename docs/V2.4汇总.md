# V2.4 汇总

## 1. 方法定位

`V2.4` 是当前 CybORG `4-objective semantic safety` 主线中已经完成 `3-seed` 验证的方法版本，方法名固定为：

- `ours_stage2_fair_critical_safe_v2_4_4obj`

它的核心目标不是单纯提高 reward-space 指标，而是让 defender 在 `enterprise foothold -> pre-critical window -> critical breach` 这一攻击推进链中，稳定地把交互拦截在 `pre-critical` 阶段，从而做到：

- 不进入真实 critical breach
- 保留部署可接受性
- 仍然维持多目标候选集质量

当前主结论可以概括为一句话：

> `V2.4` 实现了稳定的 `pre-critical containment`，支持“breach-free but not risk-free”的表述。

相关主记录见：

- [docs/results.md](./results.md)
- [docs/TASKS.md](./TASKS.md)
- [paper/main.tex](../paper/main.tex)

## 2. 从旧线到 V2.4 的收敛过程

当前语义安全线并不是从一开始就直接稳定到 `V2.4`。按现在仓库里的记录，方法经历了从旧 `Critical-First / V2.1 / V2.2 / V2.3` 到 `V2.4 pre-critical containment` 的收敛过程。

收敛逻辑大致是：

1. 旧线已经明确暴露出问题：单纯 gate、target 或 selector 的局部修补，不能稳定把 `ever_critical_breach_rate` 从高位拉下来。
2. 方法焦点从“末端补救”转向“是否能在 pre-critical 阶段稳定响应 enterprise foothold”。
3. 最终收敛到 `V2.4` 的过程性特征：
   - defender 在 pre-critical 阶段的动作几乎完全变成 `restore`
   - `decoy` 不再承担主响应角色
   - pre-critical 关注点稳定落在已 compromised 的 enterprise 目标上
4. 因此，`V2.4` 的方法标签不再是旧的 stop-loss 或 deployability-aware 局部修补，而是更明确的：
   - `pre-critical containment`

当前仓库里对这条收敛结论的直接记录见：

- [cmorl_cyborg/docs/TASKS.md](../cmorl_cyborg/docs/TASKS.md)
- [docs/results.md](./results.md)

三颗 seed 当前都已经完成，且：

- `3/3 seeds pilot_passed = true`
- selected policy 分别为：
  - `seed_0007 -> stage2_ext_008_obj_0`
  - `seed_0011 -> stage2_ext_005_obj_1`
  - `seed_0019 -> stage2_ext_005_obj_2`

三颗 seed 的 selected replay20 semantic audit 聚合结果见：

- `selected mean_critical_dwell_steps = 0.0000`
- `selected high_confidence_env_run_rate = 0.0000`
- `selected Tier 1 Near-Miss = 1.0000`
- `selected precritical restore step rate = 1.0000`
- `selected precritical decoy step rate = 0.0000`

这说明：

- `Tier 2 / Tier 3` 的 critical breach 已经被消掉

因此，最稳妥的表述不是“完全无风险”，而是：

## 5. 方法上真正成立的点

从当前证据看，`V2.4` 真正成立的不是“全面无条件最优”，而是下面这几个更具体、更稳的点：

1. 它已经稳定实现了 `pre-critical containment`。
2. 它在三颗 seed 上都消除了真正的 critical breach。
3. 它的过程性行为是可解释的：
   - pre-critical 阶段稳定 `restore`
   - 不再依赖 `decoy` 作为主响应
   - 对已 compromised enterprise 目标保持稳定聚焦
4. 它在 deployment-time 上已经给出了可直接比较的候选行。

## 6. 当前仍然存在的限制

当前证据也明确说明，`V2.4` 还不能被表述成更强的版本：

- 不能说“完全消除了 cyber risk”
- 不能说“在所有维度上都无条件最优”
- 不能直接把当前 `V2.4 table_a` 当成旧 `3-objective Table A` 的替代品

最主要的限制有两个：

1. `Tier 1 Near-Miss` 仍然是 `1.0`
2. `table_a` 目前是 `4-objective` 独立口径，和旧主表 A 不共口径

## 7. 当前最合理的论文摆放方式

按照现在仓库中的判断，最稳妥的摆放方式是：

- `V2.4 table_b`：
  - 作为主表新增方法行候选
  - 或作为替换当前 `ours_stage2` 主结果行的候选
- `V2.4 table_a`：
  - 先作为补充表
  - 或作为独立 semantic-safety set-quality 表

如果后续要把 `V2.4` 全面推进为论文主线，下一步必须明确：

- 是否把主文从旧 `3-objective` 完整升级到 `4-objective semantic safety`
- 是否把 `Table A` 和 `Table B` 的方法集合统一到新的 `4-objective` 协议
